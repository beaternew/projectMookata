Java

package และ import

package คือที่อยู่ของไฟล์ เหมือนเลขห้อง ไฟล์ MemberDao.java อยู่โฟลเดอร์ dao จึงเขียน package com.example.bonussuki.dao;

import คือบอกว่า "จะใช้คลาสจากห้องอื่นนะ" เขียนไว้บนสุด ถ้า NetBeans ขีดเส้นแดงว่าหาคลาสไม่เจอ กด Ctrl+Shift+I (Mac: ⌘+Shift+I) ให้มันเติม import ให้

class กับ object

class คือแบบพิมพ์ object คือของที่พิมพ์ออกมาจากแบบ

คลาส Member คือแบบฟอร์มบัตรสมาชิก มีช่องชื่อ เบอร์ แต้ม ส่วน new Member("สมชาย", "081…", null) คือบัตร 1 ใบที่กรอกแล้ว สร้างกี่ใบก็ได้จากแบบเดียว

ในโปรเจกต์นี้ 1 คลาส = 1 ไฟล์ และชื่อไฟล์ต้องตรงกับชื่อคลาส

ตัวแปรและชนิดข้อมูล

ทุกตัวแปรต้องบอกชนิดก่อนชื่อเสมอ

ชนิดเก็บอะไรตัวอย่างในโปรเจกต์
Stringข้อความรหัส "M001", ชื่อ, วันที่ "2026-11-10"
intจำนวนเต็มแต้มสะสม, จำนวนคน
doubleตัวเลขมีทศนิยมราคา 299.0, ยอดเงิน
booleanจริง/เท็จisManager()
Integer, Doubleตัวเลขแบบที่เป็น null ได้เงินที่รับ (ยังไม่จ่าย = null)

null = "ไม่มีอะไรอยู่เลย" ถ้าเรียกเมธอดของตัวแปรที่เป็น null โปรแกรมพังด้วย NullPointerException

constructor

เมธอดพิเศษที่ชื่อเหมือนคลาส ไม่มีชนิดที่คืน ทำงานตอน new มีไว้เติมค่าเริ่มต้น

คลาสเดียวมีได้หลายตัว ขอแค่รับของต่างกัน Member มี 3 ตัว: ครบทุกช่อง / ไม่มีรหัส / ว่างเปล่า

this.memberId = memberId; → this.memberId คือช่องของกล่อง ส่วน memberId เฉย ๆ คือค่าที่ส่งเข้ามา

method: รับของ ทำงาน คืนของ

หัวเมธอดอ่านได้แบบนี้: public Member get(String memberId) = ใครก็เรียกได้ (public) · คืน Member · ชื่อ get · รับ String 1 ตัว

void = ไม่คืนอะไร · return = ส่งค่ากลับแล้วออกจากเมธอดทันที

private + getter/setter

ช่องในกล่องตั้งเป็น private คนนอกแตะตรง ๆ ไม่ได้ ต้องผ่าน getX() (ขอดู) และ setX() (ขอเปลี่ยน)

ทำไมต้องยุ่งยาก? วันหนึ่งถ้าอยากเพิ่มการเช็ก เช่น "แต้มห้ามติดลบ" ก็แก้ใน setter ที่เดียว ไม่ต้องไล่แก้ทุกไฟล์

static และค่าคงที่

static = เป็นของคลาส ไม่ใช่ของ object แต่ละตัว มีชุดเดียวทั้งโปรแกรม เรียกผ่านชื่อคลาสได้เลย เช่น DatabaseHelper.getConnect(), Session.isManager()

static final = ค่าคงที่ เปลี่ยนไม่ได้ ตั้งชื่อตัวใหญ่ เช่น BAHT_PER_POINT = 25

interface และ implements

interface = ใบสัญญา บอกแค่ชื่อเมธอดที่ต้องมี ไม่มีเนื้อในเมธอด

implements = เซ็นสัญญา คลาสนั้นต้องเขียนเมธอดครบทุกตัว ไม่งั้น compile ไม่ผ่าน

ในโปรเจกต์มี 2 ใบสัญญา: Dao<T> (DAO ทุกตัว) และ Refreshable (หน้าจอที่โหลดใหม่ได้)

List และ ArrayList

List<Member> = รายการของ Member หลายตัวเรียงกัน <Member> บอกว่าข้างในเป็นอะไร

new ArrayList<>() สร้างรายการว่าง · list.add(x) เพิ่ม · list.size() นับ · list.get(0) หยิบตัวแรก

if และ loop

if (เงื่อนไข) { … } else { … } = ถ้าจริงทำอันแรก ไม่งั้นทำอันหลัง

for (BillLine line : lines) = "หยิบทีละ line จาก lines" ทำซ้ำจนครบ · while (rs.next()) = ทำซ้ำตราบที่ยังมีแถว

ตัวเชื่อม: && และ · || หรือ · ! ไม่

== กับ .equals()

ตัวเลขเทียบด้วย == ได้ แต่ ข้อความต้องใช้ .equals()

== กับข้อความถามว่า "เป็นกระดาษแผ่นเดียวกันไหม" ส่วน .equals() ถามว่า "เขียนเหมือนกันไหม" รหัสผ่านที่พิมพ์มากับที่อ่านจากฐานข้อมูลเป็นคนละแผ่น ใช้ == จะได้ false ทั้งที่รหัสถูก

throw: โยนข้อผิดพลาด

เมื่อ service เจอข้อมูลผิดกฎ มันจะ throw new IllegalArgumentException("ข้อความ") = หยุดทำงานตรงนั้น แล้วโยนกระดาษข้อความขึ้นไปให้คนที่เรียก

หน้าจอรับกระดาษด้วย catch แล้วเอาข้อความไปโชว์ ผู้ใช้จึงเห็น "เบอร์โทรต้องเป็นตัวเลข 10 หลัก" แทนโปรแกรมค้าง

try-catch: ลองทำ ถ้าพังให้รับมือ

try { โค้ดที่อาจพัง } catch (ชนิดข้อผิดพลาด ex) { ทำอะไรเมื่อพัง }

ถ้าบรรทัดใดใน try พัง Java กระโดดไป catch ทันที บรรทัดที่เหลือใน try ไม่ทำ ex.getMessage() = ข้อความที่ถูกโยนมา

finally: ทำเสมอ (แบบ Lab 8)

finally { … } ต่อท้าย try-catch ทำทุกครั้ง ไม่ว่าจะสำเร็จ พัง หรือ return ไปแล้ว เหมาะกับ "เก็บกวาด"

DAO ทุกตัวในโปรเจกต์ใช้รูปเดียวกัน:

  1. ยืม conn จาก DatabaseHelper
  2. ประกาศ stmt, rs = null ไว้นอก try
  3. try: เตรียม SQL ใส่ค่า ส่งไป อ่านผล
  4. catch: จด Log คืน null / -1
  5. finally: closeQuietly(rs, stmt) ไม่ปิด conn

lambda และ this::method

บางครั้งเราต้อง "ส่งงาน" ให้คนอื่นไว้ทำทีหลัง เช่น "ถ้าปุ่มถูกกด ให้ทำสิ่งนี้"

e -> { … } คือ lambda = งานสั้น ๆ ไม่มีชื่อ · this::btnSaveActionPerformed คือ method reference = "ส่งเมธอดนี้ของฉันไป" NetBeans ใช้แบบหลังผูกปุ่มทุกปุ่ม

UPDATE ตาราง SET คอลัมน์ = ค่าใหม่ WHERE เงื่อนไข ลืม WHERE = แก้ทุกแถวในตาราง

DELETE: ลบ

DELETE FROM ตาราง WHERE เงื่อนไข ลืม WHERE = ลบหมดทั้งตาราง

PreparedStatement และเครื่องหมาย ?

แทนที่จะเอาข้อความมาต่อกันเป็น SQL เราเขียน ? ไว้ แล้วใส่ค่าทีหลังด้วย stmt.setString(1, ค่า)

ทำไม? ถ้าต่อข้อความเอง แล้วมีคนพิมพ์ชื่อผู้ใช้ว่า ' OR '1'='1 SQL จะกลายเป็น "เอาทุกบัญชี" แล้วล็อกอินได้โดยไม่รู้รหัส นี่เรียกว่า SQL Injection ใช้ ? แล้วฐานข้อมูลจะถือว่าค่าที่ใส่เป็นข้อความธรรมดาเสมอ

ใช้ executeQuery() กับ SELECT · ใช้ executeUpdate() กับ INSERT / UPDATE / DELETE

ResultSet: ผลที่ได้จาก SELECT

ResultSet เหมือนเคอร์เซอร์ชี้ "ก่อนแถวแรก" rs.next() เลื่อนลง 1 แถว คืน true ถ้ามีแถว แล้วอ่านค่าด้วย rs.getString("ชื่อคอลัมน์"), rs.getInt(…), rs.getDouble(…)

JOIN: เอา 2 ตารางมาต่อกัน

ตาราง Bill_Product เก็บแค่ "บิลไหน สั่งเมนูรหัสอะไร กี่จาน" ไม่มีชื่อและราคา ต้อง JOIN กับตาราง Product โดยจับคู่ด้วย Product_ID

Transaction: ทั้งหมดหรือไม่เลย

การจ่ายเงิน 1 ครั้งต้องแก้ 4 ตาราง (บิล สต็อก แต้ม โต๊ะ) ถ้าแก้ไปแล้ว 2 ตารางแล้วพัง ข้อมูลจะเพี้ยน

Transaction แก้ปัญหานี้: setAutoCommit(false) เริ่ม → ทำทุกขั้น → commit() บันทึกพร้อมกัน · ถ้าพัง rollback() ย้อนกลับทั้งหมด

ไฟล์อื่นในชั้นนี้ (20)

เขียนแบบเดียวกับไฟล์ข้างบน ต่างแค่ชื่อตาราง ชื่อช่อง และกฎ กดชื่อเพื่อดูรายละเอียด

  • BillDetailDialogหน้าต่างใบเสร็จ 1 ใบ: หัวบิล รายการ ยอดรวม ส่วนลด สุทธิ เงินรับ เงินทอน
  • BillPanelตารางบิลย้อนหลัง ดูอย่างเดียว ดับเบิลคลิกแถวเพื่อเปิดใบเสร็จ
  • CheckStockPanelหน้าตรวจนับสต็อก: เริ่มรอบ แก้ช่อง "นับได้" ในตาราง แล้วยืนยัน
  • DashboardPanelหน้าสรุปของผู้จัดการ: การ์ดตัวเลข 3 ใบ กราฟเส้นรายเดือน กราฟวงกลม (ใช้ไลบรารี jfreechart)
  • EmployeePanelหน้า CRUD พนักงาน และบัญชีล็อกอินของพนักงานคนนั้นในหน้าเดียวกัน
  • ExpensePanelหน้า CRUD ค่าใช้จ่าย แนบรูปใบเสร็จได้
  • HomePanelหน้าแรกหลังล็อกอิน: ทักทาย สรุปของวันนี้ วัตถุดิบใกล้หมด ปุ่มลัดไปหน้าขาย
  • OpenTableDialogหน้าต่างเลือกโต๊ะและจำนวนคนก่อนสั่งอาหาร โต๊ะที่เปิดอยู่แล้วกลับมาสั่งต่อได้
  • PaymentDialogหน้าต่างชำระเงิน: ค้นสมาชิกด้วยเบอร์ เลือกโปร เลือกเงินสด/QR โชว์เงินทอนทันที
  • PayrollPanelหน้า CRUD เงินเดือน ยอดสุทธิคำนวณให้เอง
  • ProductPanelหน้า CRUD สินค้า/เมนู และรูปเมนู
  • StockItemPanelหน้า CRUD วัตถุดิบ โชว์ว่าตัวไหนใกล้หมด
  • VendorPanelหน้า CRUD ผู้จัดจำหน่าย หน้าตาแบบเดียวกับ MemberPanel
  • WorkTimePanelหน้าลงเวลาเข้า-ออกงาน มีนาฬิกาเดินอยู่ พนักงานลงเวลาของตัวเองได้
  • Formตัวช่วยของหน้า CRUD: ตารางที่แก้ในเซลล์ไม่ได้ ช่องว่างกลายเป็น null แปลงข้อความเป็นตัวเลข
  • ImageLoaderโหลดรูปจากโฟลเดอร์ images/ ถ้าไม่มีรูปก็วาดรูปแทนให้ (กล่องสีเทา หรือวงกลมตัวอักษร)

  • Refreshableสัญญาว่า "หน้านี้โหลดข้อมูลใหม่ได้" MainFrame เรียก refresh() ทุกครั้งที่เปิดหน้า
  • ThaiFontตั้งฟอนต์ที่อ่านภาษาไทยได้ให้ทั้งโปรแกรม เรียกครั้งเดียวใน main
  • Themeเก็บสีทั้งหมดจาก Figma และวิธีแต่งปุ่ม ตาราง การ์ด หัวข้อ ทุกหน้าจอเรียกที่นี่ ห้ามพิมพ์สีเอง

ผ่าน 3 ชั้น 7 ไฟล์ แก้ 4 ตารางใน transaction เดียว ลองนึกภาพ: โต๊ะ T02 มา 4 คน สั่งบุฟเฟต์หมู 4 ชุด จ่ายเงินสด 1,000 บาท ใช้โปร P001

  1. 1

    คนกดปุ่ม "ชำระเงิน" ui

    ปุ่ม btnCheckout ถูกผูกกับเมธอดนี้ไว้ใน initComponents พอกดก็เข้ามาที่นี่ ถ้ามีบิลอยู่ เปิดหน้าต่างชำระเงิน

  2. 2

    หน้าต่างชำระเงินเปิดขึ้นและรอ ui

    หน้าต่างแบบ modal: setVisible(true) จะค้างอยู่บรรทัดนี้จนกว่าหน้าต่างจะปิด แล้วค่อยตอบกลับว่าจ่ายสำเร็จ (paid) หรือไม่

  3. 3

    พนักงานกด "ยืนยัน" ui

    อ่านวิธีจ่ายและเงินที่รับ แปลงเป็นตัวเลข แล้วส่งทุกอย่างให้ posService.checkout(...) หน้าจอไม่คิดเงินเอง

  4. 4

    เริ่ม transaction service

    ปิด auto-commit: จากนี้ทุกคำสั่ง SQL ยังไม่ถูกบันทึกจริง จนกว่าจะ commit

  5. 5

    รวมยอด คิดส่วนลด เช็กเงิน service

    รวมยอดจากรายการในบิล ให้ PromotionService คิดส่วนลด หักได้ยอดสุทธิ ถ้าเงินไม่พอ throw ทันที (ยังไม่มีอะไรถูกบันทึก)

  6. 6

    PromotionService คิดส่วนลด service

    เลือกตามรหัสโปรด้วย switch เช่น สมาชิกลด 10% · ไม่ใช้โปร = ส่วนลด 0

  7. 7

    เติมข้อมูลลงบิล แล้วบันทึก service

    ตั้งค่าทุกช่องของบิล แล้วสั่ง billDao.update(bill) ถ้าได้ null → require โยนข้อผิดพลาด

  8. 8

    BillDao เขียน UPDATE dao

    SQL ตัวจริงที่แก้แถวบิล ใช้ ? หลายตัวเรียงตามคอลัมน์ ใช้ connection ตัวเดียวกับ PosService จึงอยู่ใน transaction เดียวกัน

  9. 9

    ตัดสต็อกตามสูตร dao

    คำสั่งเดียวตัดวัตถุดิบทุกตัวที่เมนูในบิลใช้: จำนวนที่สั่ง × ปริมาณต่อจานในตาราง BOM (บุฟเฟต์หมู 4 ชุด × 0.15 กก. = หมู 0.6 กก.)

  10. 10

    บวกแต้มสมาชิก service

  11. 11

    คืนโต๊ะ dao

    โต๊ะกลับเป็น "ว่าง" ให้ลูกค้าโต๊ะถัดไป

  12. 12

    commit หรือ rollback service

    ทุกขั้นผ่าน → commit() บันทึกพร้อมกันทีเดียว · พังขั้นไหน → rollback() ย้อนกลับทั้งหมด แล้วส่งข้อผิดพลาดต่อ · สุดท้ายเปิด auto-commit คืน

  13. 13
